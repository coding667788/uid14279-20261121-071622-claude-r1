为场地安保设计离线盲巡检调度。输入是一组有序时隙、巡检员、检查点和每名巡检员已完成的训练及每个点要求的训练。只有已完成该点要求全部训练的人可到访。每名巡检员每个时隙最多占一个点，连续时隙移动须符合输入的可达矩阵，每条可达转移附有非负移动成本；允许空闲，空闲保留原位置。每个检查点要求两名分别来自不同班组的人在指定连续窗口内先后独立到访，两次之间至少间隔输入规定的时隙。相同点可同时分配给多人，但同一时隙不能形成有先后的独立证据。每名巡检员对同一检查点最多为一个窗口提供见证，一次访问也只能供一个窗口；多窗口可以重叠。冻结的既有到访必须保留，不视作新访问；重新分配其见证归属是允许的。
schedule 求出覆盖所有必须检查的窗口的计划，依次最小化新到访次数、移动成本及按时隙和人排序的 (时隙, 人, 点, 窗口) 序列。无解输出最小不可满足的窗口集合，以升序窗口 ID 决胜，并给出删去其中任一个后的可行见证，既有到访和人员约束保持固定。check 可独立复核任意完整计划。测试包含局部可达但连续转场不可能、已到访被两个窗口同时争用、同组两人不能互证、等成本决胜、空闲保留位置。支持小而非玩具规模，至少 10 人、12 时隙、12 个窗口，说明剪枝为何完整。

排班分成实际发布的主计划和在指定揭晓时隙确认的应急计划。输入列候选缺席情景，每个情景给揭晓时隙和从该时隙起缺席的人员集合；情景之间互斥，另有无人缺席情景。揭晓前的全部移动、访问和既有见证归属必须一致，揭晓之后允许在该情景中重新调度，但不能把揭晓前的访问换作另一个窗口证据。若两个缺席情景到某个时隙为止同样没有揭晓，则这些时隙的决定也必须一致。既有冻结访问永远不得更改，事后与缺席直接冲突的情景应报告输入冲突。优化目标改为先最小化各情景中新访问次数的最大值，再最小化各情景移动成本之和，再比较按情景 ID 排序的计划列表。输出主计划及各时隙可触发的备用前缀，check 要独立核验全部情景和所有不可提前知道的分叉。测试包含每个情景单独可排却不存在共同前缀、较远主路线才允许替补连续转场、已发生访问不能被事后改填、同一时刻揭晓的不同分支和无人缺席情景。用独立穷举核对 4 人 5 时隙的小案。

使用 Windows 原生 Python 3.12、标准库和 CPU，从空仓库实现，所有夹具用本地虚构数据。命令格式为 python -m solution <命令> CASE.json，涉及持久状态的命令带 --db DB.sqlite。标准输出为 UTF-8 JSON，同一逻辑输入产生同一结果；结构错误给出可定位的错误码及字段位置。交付可直接运行的样例、README（含完整输入输出定义与复现命令）和可用 python -m unittest discover -s tests -v 执行的断言测试。
